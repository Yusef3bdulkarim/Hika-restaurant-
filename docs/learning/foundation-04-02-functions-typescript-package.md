# foundation-04-02 — Functions TypeScript package

<!-- Written by Claude. Short bullets only. Gemini explains ONLY what is written here + the diff. -->

## Problem
- Server-trusted logic (prices, promos, points, order rules) will live in Cloud Functions. We need a compiling, strictly typed and linted package before the first real function (E5).

## Assumptions
- **TypeScript `~6.0.3`, not latest 7.0.2** — `typescript-eslint` 8.74 supports `typescript >=4.8.4 <6.1.0`; `~` keeps upgrades inside 6.0.x. Move to TS 7 when `typescript-eslint` supports it.
- Added `@types/node@24` (not in the plan) — `firebase-admin` types need Node types; major 24 = runtime.
- `index.ts` only initializes the Admin SDK; no functions yet.

## Decisions
| Decision | Alternatives considered | Why this one | Trade-off |
|---|---|---|---|
| ES modules (`"type": "module"`, `module: nodenext`) | CommonJS (`firebase init` default) | Modern Node standard; supported by Cloud Functions; matches Vitest/ESLint configs | Relative imports need `.js` extensions |
| `strict` + `noUnusedLocals/Parameters` + `noImplicitReturns` | Default `strict` only | Money logic — catch dead and half-handled code at compile time | More compiler errors to fix |
| ESLint flat config + `strictTypeChecked` | `firebase init` `.eslintrc` + google style | Current ESLint format; type-aware rules catch unsafe `any`, floating promises | Lint is slower (uses type info) |
| `disableTypeChecked` for `*.mjs` | Type-check config files | Config file is not in `tsconfig` → would error | — |
| Versions pinned at install time (latest stable, TS exception above) | Older template versions | Project rule: latest stable | — |
| `functions/.gitignore` for `lib/` + `node_modules/`; root ignores `.firebase/`, `*-debug.log` | Commit build output | Build output is generated by `predeploy` | — |

## Thinking steps
1. Check latest versions and **peer ranges** before installing — found the TS 7 / typescript-eslint gap.
2. Minimal `package.json` (engines 24, build, lint), then install.
3. Strict `tsconfig`; first build failed (`Cannot find name 'http'`) → added `@types/node@24` + `types: ["node"]`.
4. Lint clean; Functions emulator loads the package with Node 24.

## Files
- `functions/package.json` / `package-lock.json` — deps, engines, scripts.
- `functions/tsconfig.json` — strict TS → `lib/`.
- `functions/eslint.config.mjs` — flat config, type-aware rules.
- `functions/src/index.ts` — Admin SDK init (entry point).
- `functions/.gitignore`, root `.gitignore` — build output and Firebase logs.

## Principles & patterns
- **Check compatibility, not just "latest"** — peer dependency ranges decide what "latest stable" can be.
- **Type-aware linting** — catches floating promises (unawaited Firestore writes) — overkill for a few lines of glue code.
